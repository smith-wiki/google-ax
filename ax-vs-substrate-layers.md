# AX packages a workload for Substrate; Substrate runs its actor

**Substrate already can run an arbitrary container.** It gives you an `ActorTemplate`, an `Actor`, worker capacity, request routing, isolation, and snapshot-based suspend/resume. It has no opinion about whether that container is a counter server or an AI agent ([Substrate architecture: resource split](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/architecture.md#L205-L260), [actor activation](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/architecture.md#L439-L456)). **AX adds an application-facing declaration and control plane** that translates a `Task` and its bound `Workspace` into a Substrate actor and starts a prescribed runner inside it ([AX design](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/DESIGN.md#L3-L44), [reconciler](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/controller/reconciler.go#L94-L218)).

| Layer | Owns | Does not own |
|---|---|---|
| **Your agent application** | Prompt, model calls, tools, session, planning, delegation, and result handoff. | Sandbox placement and snapshot mechanics. |
| **AX** | `Task` image/command/env and lifecycle, reusable `Workspace` declarations, `Model` declarations, `ax` CLI and gRPC API, reconciliation into Substrate actors, and the in-sandbox `ax-task-runner` that prepares the workspace and launches the child command. | The child agent's reasoning, task graph, conversation, or success protocol ([AX concepts](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L5-L38), [runner contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L9-L47)). |
| **Agent Substrate** | `ActorTemplate`/`Actor`, scheduling into warm workers, sandbox execution, actor traffic routing, checkpoints, suspend/resume. | Git checkout, AX Task/Workspace semantics, or the user's agent loop ([architecture](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/architecture.md#L304-L354)). |
| **Kubernetes** | Worker Pods and infrastructure resources. | The per-actor high-churn lifecycle, which Substrate keeps in its own control plane ([resource split](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/architecture.md#L205-L260)). |

A concrete translation: you declare an AX `Task` with an image, a command, and a `Workspace` containing a Git source. AX stores and reconciles that declaration, creates a same-name Substrate actor, and supplies the specifications to its runner. Substrate finds worker capacity and starts the sandbox; the runner checks out the repository and invokes the command. Only **that command**, if you supplied an agent program, performs agent work ([AX reconciler](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/controller/reconciler.go#L94-L169), [workspace setup](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/workspace/setup.go#L76-L127), [runner launch](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/runner/runner.go#L155-L187)). Without AX, you can create a Substrate actor yourself but must assemble the workspace setup, task-facing API, runner, and agent integration yourself; AX is convenience and policy surface *above* the sandbox, not a replacement runtime.

**What is real at the inspected AX revision (`e09ed1b`)?** Its `Workspace` declaration is broader than implementation: Git checkout and an optional bootstrap goal work, but MCP materialization and skill registry resolution do not. A `Model` resource does not select the model for a Task's agent; `TaskSpec` has no model reference. `Ready` is sandbox readiness, not child-command success. AX requests `Data` snapshots of `/workspace`, so resumption starts a fresh process instead of restoring the agent's RAM, even though newer Substrate can support full-memory snapshots ([workspace implementation](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/workspace/setup.go#L76-L127), [missing materialization](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/workspace/setup.go#L261-L269), [Task schema](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/pkg/apis/v1alpha1/ax.proto#L70-L90), [runner and snapshot contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L21-L47), [AX snapshot policy](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/substrate/client.go#L238-L270)).

See [the Substrate architecture](what-is-agent-substrate.md) for the physical execution layer and [the AX-to-agent interface](brain-to-ax-interface.md) for the missing result and coordination protocol.
