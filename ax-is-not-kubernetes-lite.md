# AX is a specialized layer on Kubernetes, not a smaller Kubernetes

**The analogy is useful only at the interface:** `ax apply` and `ax watch` resemble `kubectl`, and AX exposes declarative `Task`, `Workspace`, and `Model` resources. But AX does **not** replace a Kubernetes cluster. Real AX Tasks require **Agent Substrate running on Kubernetes**; AX adds its own API, controller, and Redis state store on top ([AX overview and prerequisites](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L11-L13), [quick-start prerequisites](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L59-L91), [AX architecture](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/DESIGN.md#L3-L44)).

Kubernetes manages the physical worker Pods. Substrate manages isolated logical actors over that warm capacity; AX turns a `Task` into one such actor and prepares its Git/tools workspace. AX keeps rapidly changing task records in Redis rather than representing every task as a Kubernetes CRD. This is a specialized execution control plane, not a general replacement for Pods, Deployments, or Jobs ([Substrate actor/worker model](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/glossary.md#L19-L50), [AX design](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/DESIGN.md#L3-L44)). Even as a Job alternative its current Task lifecycle is incomplete: the control plane does not receive the child command's exit code ([runner contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L41-L43)).

**For three agents**, this stack is not simpler than running three ordinary processes/containers; it adds Substrate and AX operations without providing their shared session, dependency graph, or result assembly. Its intended advantage arises when *operating many isolated, resumable agent sandboxes* is the hard part—not when designing the team workflow is the hard part. This is an architectural fit judgment, not an observed benchmark ([why AX exists](ax-solves-agent-operations.md), [who coordinates agents](brain-to-ax-interface.md), [why k3s alone is insufficient](remote-k3s.md)). No cluster or code was run for this conclusion.
