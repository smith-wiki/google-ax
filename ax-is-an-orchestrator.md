# AX is the orchestrator, not the agent harness

This note describes commit `e09ed1b`. AX labels its concepts, protocols, and specifications as actively changing and warns of breaking changes before a stable release. ([README warning](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L6-L9))

## The first-party workflow

The intended operator path is:

1. **Provision the runtime.** Bring a Kubernetes cluster, install Agent Substrate, and verify its `ate-system/api` service. Then install `ax` and run `make deploy AX_IMAGE_REPO=...`; that deploys Redis and the AX control plane into `ax-system`. ([README: prerequisites and deployment](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L61-L91))
2. **Declare resources.** A `Workspace` describes Git checkouts, MCP servers, and skills; a `Task` selects an image and command, resources, environment, workspace bindings, and optional debug access; a `Model` names a provider/model and Kubernetes-secret credential. ([Concepts: Task and Workspace](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L5-L32), [Concepts: Model](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L34-L38), [annotated manifests](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/manifests.md#L5-L34))
3. **Apply and operate.** `ax apply -f ...` creates or updates the declarations; `ax watch` observes readiness and lifecycle conditions; `ax ssh` reaches the guest services when `spec.debug: true`; `ax suspend` and `ax resume` drive the actor lifecycle. ([README: first task](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L93-L107), [lifecycle conditions](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L11-L20), [debug/SSH contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/sandbox.md#L28-L33))
4. **Connect to an application protocol if the agent exposes one.** Tasks do not receive individual Services or Ingresses. Cluster, laptop, and gRPC callers route through Substrate's `atenet-router` with `ate-target-actor: <atespace>/<task>`; the router wakes a suspended actor before proxying. This is generic transport, not a chat API. ([Networking](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/networking.md#L1-L31))

The developers describe a single Task as either a whole job or the root of a tree of Tasks; AX deliberately does not model the agent's planning, delegation, retries, or message protocol. That is an architectural intention, not a supplied multi-agent workflow ([Task concept](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L5-L9), [control-plane API](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/pkg/apis/v1alpha1/ax.proto#L24-L51)).

## Where the actual agent goes

AX starts `/usr/local/bin/ax-task-runner` as PID 1. The default runner prepares the workspaces, starts `spec.command` as a child in the first workspace, supplies `AX_METADATA_URL` and `spec.env`, and keeps its metadata/guest server alive after that child exits. ([runner launch contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L9-L26), [sandbox boot sequence](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/sandbox.md#L1-L10))

Therefore the concrete integration recipe is: package the agent program and its message loop in an image, set that image in `Task.spec.image`, and put its argv in `Task.spec.command`. If only extra tools are needed, extend the default image; for lifecycle hooks, embed the Go `runner` package; for a different supervision/layout model, implement the runner contract and install it at `/usr/local/bin/ax-task-runner`. ([three customization levels](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L58-L151))

The `Model` resource does **not** turn a task into an agent. First-party wording says it configures the LLM “the platform itself uses,” for example while planning a workspace from a goal; `TaskSpec` has no model/session/message field. ([README resource table](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L45-L57), [`TaskSpec` schema](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/pkg/apis/v1alpha1/ax.proto#L60-L91))
Similarly, a workspace binding's optional `goal` invokes the bundled Antigravity agent only to prepare that environment before the task command starts; it is not the task's ongoing agent loop. ([workspace materialization](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L22-L32), [boot order](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/sandbox.md#L3-L10))

## The getting-started demo is an infrastructure demo

This distinction is easy to miss because the checked-in quick-start resources do not launch an agent at all. `examples/task.yaml` supplies an image and workspace but no `command`; `examples/simple.yaml` explicitly calls itself the smallest useful task and also has no command. ([task example](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/examples/task.yaml#L15-L38), [simple example](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/examples/simple.yaml#L15-L33)) The default runner's actual behavior for an empty command is to serve metadata until stopped. ([runner source](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/runner/runner.go#L167-L172))

Likewise, `demo.sh` declares only a workspace and task, waits for readiness, inspects it with `ax ssh`, and suspends it; there is no agent or message exchange in the demo. ([demo declaration and lifecycle](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/demo.sh#L144-L198))

## “Pick up exactly where it left off” means durable data in AX today

The README uses that phrase for suspend/resume and also says “checkpoint actor state.” ([README](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L45-L55), [CLI wording](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/README.md#L128-L145)) The more precise runner contract says `/workspace` is snapshotted, resume restores it into a **fresh container**, and the runner sees the same files but a **new process tree**. On suspend, PID 1 receives `SIGTERM` and must flush anything needed for resume. ([persistence contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L24-L26), [shutdown responsibility](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#L39-L47)) The implementation also requests Substrate `DATA` snapshots rather than full-memory snapshots. ([actor-template snapshot policy](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/substrate/client.go#L238-L275))

So for AX at this revision, “exactly where” must not be read as preserved RAM, stack, sockets, or a live LLM call. It means that an agent can continue **if the agent itself writes sufficient state—such as its session identifier, transcript, pending work, and checkpoints—to the durable workspace and reconstructs its process on restart**. That last sentence is an integration inference from the documented fresh-process contract, not a supplied AX feature.

## Resume, rollback, and branching are different operations

At the AX boundary, suspend and resume identify only the same `Task` by `atespace` and name; the CLI has no snapshot argument, and the controller forwards only that Task's same-name actor to Substrate. There is no AX snapshot/tag/version selector and no Task fork or clone RPC, so AX cannot choose an older checkpoint or branch Task state at this revision. ([AX lifecycle request schema](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/pkg/apis/v1alpha1/ax.proto#L253-L261), [CLI resume](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/cmd/ax/main.go#L887-L915), [Substrate adapter](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/substrate/client.go#L306-L320), [resume forwarding](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/internal/substrate/client.go#L368-L387))

The lower Substrate layer has a narrower branching primitive, but AX does not wire it through. The Substrate revision pinned by AX says `ResumeActor` restores the latest snapshot and accepts only an actor reference; it also exposes immutable `Tag`s that copy and retain the snapshot a suspended actor currently holds, plus `CreateActor.source_tag` for seeding a new actor from such a tag. It explicitly says an actor keeps no snapshot history and each suspend replaces the last. Thus a snapshot retained **beforehand** as a tag can seed one or more new actors, but an existing actor cannot ask `ResumeActor` to select an arbitrary earlier checkpoint. Substrate resource `version` is an update-concurrency field, not a checkpoint version. ([AX dependency pin](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/go.mod#L5-L8), [pinned Substrate lifecycle and Tag RPCs](https://github.com/agent-substrate/substrate/blob/672533541dbfcd29084e4de2475267088bda3651/pkg/proto/ateapipb/ateapi.proto#L24-L91), [`Actor.source_tag`](https://github.com/agent-substrate/substrate/blob/672533541dbfcd29084e4de2475267088bda3651/pkg/proto/ateapipb/ateapi.proto#L350-L389), [no-history Tag contract](https://github.com/agent-substrate/substrate/blob/672533541dbfcd29084e4de2475267088bda3651/pkg/proto/ateapipb/ateapi.proto#L1575-L1613), [resource metadata version](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/pkg/proto/ateapipb/ateapi.proto#L239-L290)) The separately reviewed newer Substrate revision also has `RevertActor`, but that discards current execution back to the same actor's **last completed** external snapshot; it still does not select an older one. ([Substrate `RevertActor`](https://github.com/agent-substrate/substrate/blob/22ba860e0f32e20713165b96abd81f6f96da620c/docs/api-guide.md#L509-L515))

AX's Task-tree language describes composition, not snapshot inheritance: one Task may be the whole job or the root or node of a tree of ordinary Tasks, while stateful branching of a running or suspended Task—including memory and workspace state—is explicitly roadmap work. AX therefore does not require one Task to be a monolithic long-lived agent. As an integration inference, an agent program could recursively create Tasks or branch files with Git, but that would be its own orchestration/data protocol, not an AX checkpoint fork. ([Task-tree intention](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md#L5-L10), [stateful branching roadmap](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/roadmap.md#L15-L23))

## What AX does not yet prescribe

Across the first-party README, guides, examples, demo, schema, and API reference, there is no official conversation/session resource, send-message RPC, transcript format/store, or end-to-end harness recipe. The control-plane API covers resource CRUD, task lifecycle, and watching; the application protocol above it belongs to the user-supplied agent. ([AX API reference](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/DESIGN.md#L46-L78))

The roadmap reinforces that boundary rather than filling it: customizable agent runtimes/system instructions/tool policies, automatic structured trajectory collection, and automatic idle suspension are future work. ([Roadmap](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/roadmap.md#L15-L40))
